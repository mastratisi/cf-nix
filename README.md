# cf-nix

Nix flake for Cloudflare's [`cf` CLI](https://github.com/cloudflare/cf) (open beta), following the
npm release feed.

The package installs the compiled CLI from the npm tarball (`dist/*.mjs`) together with its seven
runtime dependencies (miniflare, workerd, and others). Upstream is a pnpm monorepo built with
vite-plus; none of that is built here.

## Use

```
nix run github:mastratisi/cf-nix -- --version
```

In a flake-based NixOS config:

```nix
inputs.cf-nix.url = "github:mastratisi/cf-nix";
# ...
nixpkgs.overlays = [ cf-nix.overlays.default ];
environment.systemPackages = [ pkgs.cf ];
```

Systems: x86_64-linux and aarch64-linux. Binaries: `cf`, `cloudflare`.

## Known gaps

- The tarball has no lockfile. `package-lock.json` is generated by `update.sh` from the runtime
  dependencies and committed; `npmDepsHash` in `release.json` covers it.
- `workerd` (used by `cf dev`) and `sharp` ship prebuilt ELF binaries, patched with
  `autoPatchelfHook`. Only the x86_64-linux build has been run; aarch64-linux is evaluated only.

## How it stays current

- `update.sh` reads `https://registry.npmjs.org/cf/latest`, regenerates `package-lock.json`, and
  writes `release.json` (version, tarball URL, npm's SRI integrity hash, `npmDepsHash`). Needs
  `jq`, `curl`, `npm`, `prefetch-npm-deps` (all in `nix develop`).
- `.github/workflows/update.yml` runs it hourly, builds, checks `cf --version` matches, and commits
  `release.json` and `package-lock.json` if they changed.
- `package.nix` only reads `release.json`; it has no version of its own.

Update by hand: `nix develop -c ./update.sh && nix build`.
